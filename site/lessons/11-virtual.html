virtualとoverride

親クラスのポインタから、子クラスの実装を呼ぶ。

なぜvirtualが必要なのか

次のコードを考える。

親クラスのポインタで扱った場合に、意図した派生クラスの関数が呼ばれるとは限らない。そこでvirtualを使う。

virtual

override

overrideは「親クラスのvirtual関数を上書きする」という意図をコンパイラに伝える。

ポイント

綴りを間違えたり引数が違ったりすると、overrideを付けていればコンパイルエラーになる。付けていなければ「別の関数」として静かに追加されてしまう。必ず付けさせる。

ポインタからの呼び出し

update()がvirtualなら、実際のオブジェクトであるIMUの実装が呼ばれる。

変数の型（Sensor*）ではなく、実際に入っているもの（IMU）で呼び先が決まる。これが次回以降のポリモーフィズムの土台になる。

動かして確かめる

演習に入る前に、まずこのサンプルを動かして結果を見る。追加の部品は要らない。光るのはボードに載っている内蔵LEDで、それ以外はシリアルモニタの出力で確かめられる。code/examples/11-virtual-override/を開き、pio run -t uploadで書き込んでからpio device monitorで出力を見る（手順と、外付けのLEDなどをつなぐ場合は開発環境にまとめてある）。

確かめること。

  • 同じsensors[i]->update()の行から、IMUの実装とGPSの実装が呼び分けられている
  • Sensor.hppのvirtualを外すと、どちらも親の実装が呼ばれるようになる。試して出力の変化を見る
  • IMU.hppのupdate()をupdata()と書き間違えると、overrideが付いているのでコンパイラが止めてくれる
  • Sensorにvirtual ~Sensor() = default;がある理由を確認する

演習：IMU / GPS

  • Sensorにvirtual void update();を用意する
  • IMUとGPSでそれぞれoverrideして、異なるシリアル出力をする
  • Sensor*に入れて呼び、どちらが呼ばれるかを確認する
  • virtualを外すと結果がどう変わるかも試してみるさせる
