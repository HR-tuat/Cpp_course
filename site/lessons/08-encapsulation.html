カプセル化

クラス内部のデータを適切に隠し、外部から安全に操作する。

public

外部から呼び出せる。

private

外部から直接アクセスできない。

protected

通常の外部コードからはアクセスできないが、派生クラスから利用できる。

という考え方を理解する。

ポイント

「とりあえず全部privateにしてgetter/setterを付ける」のはカプセル化ではない。外部に必要な操作は何かを先に考え、それだけをpublicにする。

動かして確かめる

演習に入る前に、まずこのサンプルを動かして結果を見る。追加の部品は要らない。光るのはボードに載っている内蔵LEDで、それ以外はシリアルモニタの出力で確かめられる。code/examples/08-motor-encapsulation/を開き、pio run -t uploadで書き込んでからpio device monitorで出力を見る（手順と、外付けのLEDなどをつなぐ場合は開発環境にまとめてある）。

確かめること。

  • setSpeed(-100000)でも0、setSpeed(500)でも100になる。範囲はクラスの内部で守られている
  • speedはprivateなので、motor.speed = 500;とは書けない。試して確かめる
  • apply()もprivate。使う側が呼ぶ必要のない手続きは見せない
  • 範囲の判定をmain.cpp側に書いた場合、モータを使う場所が増えたらどうなるかを考える
